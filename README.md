# caretrack

本地设备资产登记与维修工单闭环命令行工具。数据保存在本地目录中的单个 JSON 文件，
无外部服务依赖，仅要求单进程顺序调用。

- Go 1.24 或更新版本，仅使用标准库。
- 不同 `--data-dir` 目录的数据互不影响；目录不存在时在首次成功写入自动初始化。
- 资产状态、工单、履历、请求去重信息、保养计划、备件领用记录与附件索引在一次成功写操作中原子生效（临时文件 + rename）；
  业务校验或读写失败时非零退出并说明原因，业务数据保持操作前状态。
- 已有数据文件损坏（含空文件）时报错并保留原文件，不会当空库覆盖。

## 构建与帮助

```sh
go build -o caretrack .
./caretrack            # 无参数显示应用名与帮助
./caretrack --help     # 同 -h / help
```

参数错误退出码为 2；业务失败或数据读写失败退出码为 1。

## 命令

通用参数 `--data-dir 目录` 指定本地数据目录，默认 `.caretrack`。

### 登记资产

```sh
caretrack register --asset-id EQ-001 --name 打印机 --location 一楼大厅
```

资产编号（企业资产编号）、名称、位置均不能为空；编号在同一数据目录内唯一；
新资产状态为“可用”。

### 列表

```sh
caretrack list
```

显示编号、名称、位置和当前状态；没有记录时明确输出“没有记录。”。

### 详情

```sh
caretrack detail --asset-id EQ-001
```

显示资产信息、当前状态，以及未关闭工单编号与其负责人（未派工时显示“未派工”；
无未关闭工单时显示“无”）。同时显示保养计划：有计划时显示保养内容、间隔与
下一到期日，无计划时显示“保养计划: 无”。

### 周期保养计划

```sh
caretrack plan --asset-id EQ-001 --content 更换滤芯 --first-due 2026-11-01 --interval-days 90
```

- 每项资产最多一个保养计划，建立后不可覆盖；未知资产或已有计划时拒绝。
- 保养内容非空；`--first-due` 为 0001 至 9999 年的有效公历日期（YYYY-MM-DD）；
  `--interval-days` 为正整数。日期按日历日运算，不受时区与运行时刻影响。
- 成功后显示首次到期日，并写入一条含初始计划（内容、首次到期日、间隔）的
  建立履历；下一到期日即首次到期日。

### 保养方案调整

```sh
caretrack adjust --asset-id EQ-001 --content 更换滤芯与密封圈 --first-due 2027-01-01 --interval-days 60 --reason 厂家更新保养规范
```

- 调整已有计划的保养方案：更换内容、周期起点（新首次到期日）和间隔，保留原
  保养记录。`plan` 仍只建立计划，不能覆盖；`adjust` 只作用于已有计划，
  未知资产、无计划或不合法输入拒绝。维修中、停用时也允许调整。
- 新内容非空；`--first-due` 为 0001 至 9999 年的有效公历日期（YYYY-MM-DD）；
  `--interval-days` 为正整数；`--reason` 调整理由非空。新首次到期日须**严格
  晚于**该资产所有未撤销完成的实际完成日；没有有效完成则无此限制。
- 成功后计划采用新方案，下一到期日设为新首次到期日，输出新方案与日期，
  **不补任何完成记录**；原完成的内容、日期、时间及撤销状态保留。调整追加
  一条记录前后方案、原下一到期日、理由与时间的资产级履历（`history` 可见）。
- 以该资产建立履历与各次调整履历的全库序号划分**方案段**（不按日期或数组
  位置）：`maintain` 仅完成当前段下一周期，按本段首次日加整数倍间隔推进；
  `unmaintain` 只能撤销当前段最新有效完成，可连续撤销本段，旧段完成不能再
  撤销。`detail`、`due` 采用当前方案。
- 调整不改变资产状态、工单、请求绑定或停机统计。调整为一次原子保存：校验、
  履历容量或读写失败时保留原文件字节，不留下部分变化、不消耗序号，恢复后
  可重试。

### 保养完成登记

```sh
caretrack maintain --asset-id EQ-001 --due 2026-11-01 --done 2026-11-03 --result 已更换滤芯
```

- `--due` 所填周期到期日必须等于当前下一到期日：旧周期不能重复登记，也不能
  登记尚未到期的新周期；`--done` 实际完成日不得早于周期到期日；`--result` 非空。
  无计划时拒绝。
- 成功后记录一次实际保养（写入一条含周期到期日、实际完成日和结果的完成履历），
  下一到期日推进到首次到期日加整数倍间隔所得日期中**严格晚于完成日**的最早
  日期；延期跨过的周期不生成完成记录，也不改用完成日加间隔。若下一到期日超出
  9999-12-31，整次拒绝。输出完成周期、完成履历的全库序号与下一到期日。
- 建立与完成各为一次原子保存：校验、履历容量或读写失败时保留原文件，不推进
  日期、不新增履历，恢复后可重试。

### 撤销保养完成

```sh
caretrack unmaintain --asset-id EQ-001 --seq 5 --reason 误登记，实际未保养
```

- `--seq` 为目标完成履历的全库序号（由 `maintain` 输出或 `history` 查看；完成身份
  以此序号标识，不能用到期日或报修请求标识代替），`--reason` 撤销理由非空。
- 仅可撤销该资产**当前方案段按序号最新的未撤销完成**：存在更晚有效完成时拒绝；
  方案调整后旧段的完成不能再撤销；未知资产或序号、目标不是该资产的完成、重复
  撤销均失败。撤销后可继续撤销本段此前最新有效完成；维修或其他资产事件不阻止
  操作。
- 成功保留原完成的日期、结果与时间，追加一条含目标序号、理由与操作时间的撤销
  履历，并把下一到期日恢复为该完成的周期到期日（延期跨过的周期不补记录）；
  输出目标序号与恢复的日期，`detail`、`due` 随之反映回退。
- 恢复的周期可按原 `maintain` 规则重新完成，生成新序号；旧序号的再次撤销仍被
  拒绝，不会误撤销新登记。
- 撤销为一次原子保存：校验、履历容量或读写失败时保留原文件字节，不留下部分
  变化、不消耗序号，恢复后可重试。

### 到期保养查询

```sh
caretrack due --date 2026-12-31
```

列出下一到期日不晚于 `--date` 的保养计划，显示资产编号、名称、保养内容和
到期日，按到期日再按资产编号排序；无匹配时明确提示。查询为只读：不写文件、
不初始化目录、不推进计划。停用资产不参与到期查询，但其下一到期日保持不变，
恢复使用后仍按原保存日期参与（逾期计划显示原到期日）。

保养履历与维修履历按全库唯一履历序号共同展示（`history`）。维修中资产也可
建立计划、调整方案和登记完成：保养不创建或终结工单、不消耗工单编号，不改变
资产状态、请求绑定或停机统计。

### 报修

```sh
caretrack report --asset-id EQ-001 --description 频繁卡纸 --request-id req-20261005-01
```

- 成功后返回独立工单编号（形如 `T0001`），资产变为“维修中”，并写入一条报修履历。
- 未知资产、空描述、资产已有未关闭工单时均失败，不改变状态与履历。
- `--request-id` 为调用方提供的非空标识，仅用于同一数据目录内的报修去重，
  既不是资产编号也不是工单编号：
  - 相同标识 + 相同资产 + 相同描述再次提交：返回原工单及当前状态，不新增记录。
  - 相同标识搭配不同资产或不同描述：拒绝。
  - 原工单关闭或取消后重放：仍返回原工单及其当前状态，不重开旧单，
    也不影响之后的新工单。
- 失败的新报修不会绑定请求标识；已有绑定保持不变。
- 每项资产最多有一张未关闭工单。

### 批量报修（本地清单）

```sh
caretrack batch-report --file 报修清单.json
```

一次提交多项设备故障报修，整批原子生效。清单为本地 JSON 文件（**只读**，不会被
修改），内容为一个 JSON 数组，每项包含非空的资产编号、故障描述与报修请求标识：

```json
[
  {"asset_id": "EQ-001", "description": "频繁卡纸", "request_id": "req-20261007-01"},
  {"asset_id": "EQ-002", "description": "不制冷", "request_id": "req-20261007-02"}
]
```

- 清单须完整读取并校验：空清单、JSON 格式错误、含未知字段或任一项缺少必填
  内容均整批拒绝（退出码 2），并指出清单项位置。
- 请求标识的含义与单项 `report` 完全相同，两个入口共享同一套请求绑定：
  - 批内同一标识搭配相同资产与描述的重复项合并为一项，只开一张工单、只显示
    一次；同一标识搭配不同资产或描述——无论冲突来自批内还是已有绑定——均
    整批拒绝。
  - 已有相同绑定的项为**重放**：返回原工单及当前状态，不新增履历；即使原单
    已关闭或取消、资产停用或已有后来工单，重放也不重开原单、不改变资产或
    后来工单。
  - 其余项按 `report` 规则创建工单：未知资产、停用资产、已有未关闭工单
    （含本批前项刚开出的工单，即同一资产在本批的两个不同新请求）均整批拒绝；
    旧请求重放与该资产的一项合法新报修可以共存。
- 新工单按清单首次出现顺序分配连续工单编号与报修履历序号，重复项与重放不消耗
  编号；每张新单恰有一条报修履历，所属资产变为“维修中”，不追加批次业务事件。
- 成功结果按请求标识首次出现顺序逐项显示请求标识、资产编号、工单编号、当前
  工单状态及“新增”或“重放”，每个标识只显示一次。
- 含新请求时，整批工单、状态、履历与请求绑定**一次原子保存**后才输出成功结果；
  纯重放为只读，不写文件、不初始化目录，编号或履历容量耗尽也不妨碍合法重放。
- 任一项不合法、容量不足或读写失败均整批失败并说明原因（涉及清单项时指出其
  位置），不输出部分成功结果：已有台账与输入清单字节不变，不留下部分记录或
  请求绑定、不消耗编号，恢复条件后可重试。
- 批量创建的工单与单项报修的工单无异，可正常派工、关闭或取消；保养、备件、
  附件及停机规则保持不变。

### 派工与转派

```sh
caretrack assign --ticket-id T0001 --assignee 张三 --note 首次派工，上门检修
caretrack ticket --ticket-id T0001
```

- 仅未关闭工单可派工：没有负责人时首次派工，已有负责人时转派给不同人员。
- 维修人员标识只是本地文本记录，不对应人员账户；标识与说明均不能为空。
- 成功后输出工单编号与负责人，保存变更时间与说明，并追加一条含原负责人
  （首次派工为“未派工”）、新负责人及说明的派工履历。
- 派工不创建工单、不消耗工单编号，不改变资产状态或报修请求绑定。
- 未知工单、空人员或说明、重复派给当前人员、对已关闭或已取消工单派工
  均被拒绝且不产生履历。
- 工单关闭或取消后保留最后负责人与派工履历；`ticket` 查询显示未派工或
  当前、最终负责人及工单状态。

### 关闭工单

```sh
caretrack close --ticket-id T0001 --repair-result 已更换搓纸轮
```

仅未关闭工单可关闭，维修结果不能为空；成功后设备恢复“可用”，并写入一条关闭履历。
未知工单、空维修结果、重复关闭均失败且不改动记录。

### 取消工单

```sh
caretrack cancel --ticket-id T0001 --reason 误报，设备实际正常
```

用于取消误报或不再需要维修的工单。仅未关闭工单可取消，取消理由不能为空；
成功后工单进入“已取消”终态，保存取消理由与时间，设备恢复“可用”，
详情中的未关闭工单显示“无”，可再次报修开出新工单，并写入一条取消履历。
取消不代表维修完成：不填写维修结果，不删除工单、履历或请求绑定，
工单编号不回退也不复用。未知工单、空理由、已取消或已关闭工单的取消均失败
且不改动记录；已取消工单也不能再关闭。

### 停用与恢复使用

```sh
caretrack deactivate --asset-id EQ-001 --reason 设备调拨，暂停使用
caretrack reactivate --asset-id EQ-001 --reason 调拨回库，恢复使用
```

- 两种操作都输入资产编号与非空理由，成功后显示资产编号与新状态，各追加一条
  资产级履历，保留操作时间、**原状态、新状态与理由**；不创建工单、不消耗工单
  编号。
- 仅“可用”且无未关闭工单的资产可停用，成功后变为“停用”；仅停用资产可恢复，
  成功后变为“可用”。未知资产、空理由、重复停用或恢复、维修中停用均被拒绝。
  历史记录不因恢复而删除；`list` 与 `detail` 显示停用状态。
- 停用期间拒绝新报修和保养完成登记：被拒绝的新报修不绑定新请求标识，恢复使用
  后可用同一标识重试。已有报修请求的相同重放即使资产停用仍返回原工单及当前
  状态，不开单、不改资产状态；冲突请求仍拒绝。
- 停用不删除工单、负责人、备件或附件记录；终态工单在停用期间仍可补充、撤销
  附件。维修停机统计仍只计算工单占用，停用区间不计入。
- 停用、恢复本身不改变保养内容、间隔或下一到期日，不暂停或重算周期：停用资产
  仍可建立计划、调整方案、按原规则撤销已登记完成，`detail` 仍展示计划，但 `due`
  排除停用资产。恢复后按保存的下一到期日参与到期查询，逾期计划仍显示原到期日；
  随后完成沿用按首次到期日和间隔推进的规则。
- 停用、恢复各为一次原子保存：校验、履历容量或读写失败时保留原文件字节，
  不留下部分状态或履历、不消耗序号，恢复条件后可重试。

### 维修履历

```sh
caretrack history --asset-id EQ-001
```

按操作发生顺序展示该资产的报修、派工、关闭、取消、停用、恢复使用、保养建立、保养
调整、保养完成、保养
撤销、备件领用、退回与附件登记、撤销事件，包含时间和内容（停用、恢复使用事件展示
原状态、新状态与理由；派工事件展示原负责人、新负责人与说明；取消
事件展示取消理由；保养建立事件展示内容、首次到期日与间隔；保养调整事件展示
新方案、原方案、原下一到期日与理由；保养完成事件展示
全库序号、有效或已撤销状态、周期到期日、实际完成日与结果；保养撤销事件展示
目标完成履历序号与理由；备件领用、退回事件展示工单、领用编号、备件、
数量及说明或理由；附件登记、撤销事件展示工单、附件编号、路径及说明或理由；
维修事件另含所属工单编号）；失败操作不产生履历。无履历时明确提示。

### 备件领用

```sh
caretrack withdraw --ticket-id T0001 --part-id FILTER-01 --quantity 2 --note 更换滤芯
```

- 仅未关闭工单可领用；备件编号、说明非空，`--quantity` 为正整数（表示工单用量）。
- 每次成功生成同目录唯一且不复用的领用编号（形如 `P0001`）并输出；同备件多次
  领用各自独立，领用编号用于定位记录，不用报修请求标识代替。
- 未知工单、空备件编号或说明、数量非正、已关闭或已取消工单的领用均失败，
  不产生记录与履历，也不消耗领用编号。

### 备件退回

```sh
caretrack return --withdrawal-id P0001 --quantity 1 --reason 多余退回
```

- 按领用编号退回，作用于该笔领用所属的工单；数量为正整数、理由非空。
- 允许多次部分退回，累计不得超过该笔原数量，也不能冲减另一笔；成功显示本次
  退回、累计退回及净量（原数量减累计退回）。
- 未知领用编号、超额退回、已关闭或已取消工单的退回均失败，不改动记录。
- 工单关闭或取消后保留领用记录与净量，不自动清零；旧单操作不影响新工单。
- `ticket` 查询按领用顺序显示各笔编号、备件、原数量、累计退回及净量，并按
  备件编号字典序汇总净量（全部退回的零值仍显示），无记录时显示“备件领用: 无”。
- 领用、退回各为一次原子保存：校验、数量或编号容量不足、读写失败时保留原
  文件字节，不留下部分记录、不消耗编号，恢复后可重试。

#### 顺序规则与数量边界

- 领用编号只用于定位记录；各笔领用的先后由该笔唯一领用履历的全库序号决定，
  与记录数组位置、编号大小及履历时间无关。有效台账允许记录数组乱序、履历
  序号有间隔、履历时间不递增、编号大小与领用先后不一致，无需转换即可继续
  使用。`ticket` 按此顺序展示各笔，`history` 按全库履历序号展示事件；查询
  为只读，不写文件、不初始化目录。导入时将所选资产的全部领用按源领用履历
  序号整体排序，再从目标下一领用序号依次分配新编号。
- 单笔领用与每次退回的数量均为正整数；每次退回不得超过该笔剩余可退数量
  （原数量减累计退回），超额判断不做可能整数溢出的比较。加载与保存按履历
  序号逐步核对累计退回不超过原数量、且与记录保存值一致：即使溢出回绕后的
  累计恰好等于保存值，实际超额的履历也会被拒绝。所有读取或写入台账的命令
  遇到这种矛盾均以退出码 1 结束并指出备件数量问题，不自动修复。
- 同备件各笔净量的汇总输出精确十进制整数：合计超出单笔数量范围时不回绕、
  不截断，也不因此拒绝合法台账或领用。

### 附件登记

```sh
caretrack attach --ticket-id T0001 --path ./维修照片/卡纸.jpg --note 卡纸位置照片
```

- 为工单登记本地资料附件索引：只保存资料文件的**引用**（绝对路径），不复制、
  不修改、不删除资料文件本身。未关闭、已关闭或已取消工单均可补充资料。
- `--path` 相对路径按调用时工作目录解析并保存绝对路径；登记时文件须为存在
  且可读的普通文件，否则失败（退出码 1）。`--note` 说明非空。
- 每次成功生成同目录唯一且不复用的附件编号（形如 `A0001`）并输出；每次登记
  独立，同路径不合并，也不使用报修请求标识去重。
- `ticket` 查询按登记履历序号显示全部附件的编号、路径、说明与有效或已撤销
  状态，有效附件另显示当前文件可读或不可用，无记录时显示“附件: 无”。
  文件日后消失、成为目录或不可读仅使引用不可用，不阻止撤销及其他业务，
  文件可用性也不参与整库一致性校验。

### 附件撤销

```sh
caretrack revoke --attachment-id A0001 --reason 照片拍错设备
```

- 按附件编号撤销，理由非空；成功显示已撤销，保留记录、路径、说明与理由。
- 未知编号、重复撤销均拒绝；撤销不影响同路径的其他索引或后来的工单。
- 工单关闭或取消不自动撤销附件；已撤销编号不能恢复，可重新登记为新索引。
- 登记、撤销各为一次原子保存：校验、编号或履历容量不足、读写失败时保留原
  文件字节，不留下部分记录、不消耗编号，恢复后可重试。
- `history` 按全库履历序号展示附件登记、撤销与其他事件，含时间、工单、
  附件编号、路径及说明或理由。

### 设备维修停机时长

```sh
# 单项资产
caretrack downtime --start 2026-10-01T00:00:00+08:00 --end 2026-10-02T00:00:00+08:00 --asset-id EQ-001
# 全部资产（按编号字典序）
caretrack downtime --start 2026-10-01T00:00:00Z --end 2026-10-02T00:00:00Z
```

- `--start`/`--end` 为带时区的 RFC3339 时刻，可含小数秒；起点须早于终点。
  窗口包含起点、不包含终点，按实际时刻比较（跨时区时刻会先换算到同一瞬间）。
- 停机指报修后资产被工单占用的时间：以该工单**报修履历**的时间开始，以
  **关闭或取消履历**的时间结束；取消前的占用同样计入。派工、转派不另起区间。
- 未关闭工单暂算到窗口终点：不读取运行时刻，也不改变工单与资产状态；
  未关闭工单在终点或之后才报修时记零。
- 只统计工单区间与窗口的交集，窗口外及零长度交集不贡献时长。同一资产不同
  工单可能因履历时间逆序而重叠，交集先取并集再计时，不会直接相加；不同资产
  分别计算。
- 每项资产的合计向下取整为整秒；单项查询输出编号、名称与停机秒数，全部查询
  逐行输出“编号、名称、停机秒数”，两种形式都额外输出各资产秒数之和。没有
  停机的所选资产显示零；空库明确提示“没有记录。”并显示零合计。
- 统计只依据工单归属与履历序号配对的履历时间，不使用数组位置，也不使用工单
  记录中的 `created_at`/`closed_at`/`cancelled_at` 等重复时间字段。
- 若所选资产任一**终结**工单（已关闭或已取消）的结束履历时间早于报修履历
  时间，即使该工单完全在窗口外，整次统计也以退出码 1 失败并指出资产与工单，
  不输出部分结果，也不把负时长归零；结束等于开始合法（零长度）。该规则只
  用于停机统计，不会因此拒绝原有查询与工单操作，也不自动改写时间。
- 统计为只读操作：成功或失败都不写文件、不初始化目录、不追加履历、不消耗
  工单编号，也不改变报修请求绑定；执行前仍先做整库一致性检查，损坏或关联
  矛盾的数据按原规则拒绝。

### 批量导入资产

```sh
caretrack import --source-dir /path/to/源目录 --asset-id EQ-001 --asset-id EQ-002 \
  --data-dir /path/to/目标目录
```

- 把源数据目录中所选资产连同全部工单、报修请求绑定、报修/派工/关闭/取消履历、
  停用与恢复使用履历（含当前停用/可用状态）、
  备件领用记录、附件索引（含登记/撤销履历）与保养计划（含保养建立/调整/完成/
  撤销履历）**复制**到目标目录（`--data-dir`，
  默认 `.caretrack`）。源台账始终只读，不删除原记录；同一台账不能导入自身。
  `--asset-id` 可重复给出，重复编号按一项处理，至少一项。
- 资产编号、名称、位置、状态与工单描述、终态内容、负责人等业务信息原样保留。
  保养计划随资产原样复制（当前方案的内容、首次到期日、间隔与下一到期日不变），
  全部保养履历（含调整、撤销履历）一并复制，保留段边界、顺序与时间精度，完成
  与撤销链接续，撤销履历中的目标完成序号随履历重编号同步替换；目标已有计划
  不变。导入后可继续调整方案、登记完成，或用新完成序号继续撤销。
  工单编号按源工单序号升序，从目标的下一工单序号重新分配，履历与请求绑定中
  的工单引用同步替换；领用编号按源领用履历序号整体排序后从目标的下一领用
  序号重新分配，领用记录的工单引用与退回履历中的领用引用同步更新，数量、
  累计退回与净量保持；附件编号按源登记履历序号整体排序后从目标的下一附件
  序号重新分配，附件记录的工单引用与登记、撤销履历中的附件引用同步替换，
  路径、撤销状态、说明与理由保持（只复制索引，不复制资料文件；文件当前不可
  用不使导入失败）。
  成功后输出资产数量和每张工单、每笔领用、每条附件索引的原编号、新编号，
  以及各条保养完成履历的原序号、新序号；导入后可用新完成序号继续撤销。
  目标原有记录不改编号、不改变业务含义。
- 所选履历按源履历序号排列，在目标已有最大履历序号之后依次分配新序号，保留
  原操作顺序（不按时间重排）；履历时间保留原瞬间与小数秒精度，目标原有履历
  的时间精度也不损失。导入本身不追加报修或其他业务事件。
- 资产编号在目标已存在，或所选工单的任一请求标识已在目标绑定时，整批拒绝：
  不覆盖、不合并、不改请求标识。导入后用原请求标识、资产与描述重放报修，
  返回映射后的工单及其当前状态，不创建记录；再次导入同一批资产按编号冲突
  拒绝，不作为报修请求重放。
- 操作前检查源、目标整库一致性，提交前检查合并后的数据，整批变化一次原子
  写入目标。源文件不存在（源不能当空库初始化）、所选资产不存在、台账损坏
  或关联矛盾、工单编号、领用编号、附件编号或履历序号容量不足、读写失败均说明原因并
  整批失败：两边原文件字节保持不变，不留下部分资产、履历、领用记录、附件
  索引或请求绑定，不消耗目标编号。目标无台账时在成功导入时创建。
- 导入后查询、请求重放与编号延续保持；导入的未关闭工单可继续派工、关闭、
  取消或退回备件，目标已有工单行为不变。

## 损坏与矛盾数据的处理

- 数据文件为空、不是有效 JSON，或 JSON 能解析但业务记录相互矛盾（计数器、
  请求绑定、状态、履历、保养计划、备件领用记录、附件索引中的任一类）时，所有读取与
  写入命令都报错并以退出码 1 结束，错误信息会指出问题类别。停用与恢复使用
  履历同样按全库序号重放核对：停用当时必须“可用”且无未关闭工单、恢复当时
  必须处于停用，停用期间不得新报修或登记保养完成，由履历推出的资产状态须与
  保存状态一致，停用资产不能有未关闭工单。保养数据的核对
  包括计划归属与唯一性、日期与间隔、建立、调整、完成与撤销履历链的接续（每次
  完成须接续当时下一到期日并按当时方案推进，每次调整记录的原方案与原下一到期
  日须与当时推出值一致、新首次到期日须严格晚于当时未撤销完成的实际完成日，
  每次撤销须引用当前方案段内先前同资产、未撤销且当时最新有效的完成），以及由
  履历推出的当前方案、下一到期日与计划保存值是否一致；备件数据的核对包括领用编号唯一、资产及
  工单归属、数量为正、退回指向先前领用且累计不超原数量、领用与退回在报修
  之后且终结之前，以及由履历推出的累计退回与记录保存值是否一致；附件数据的
  核对包括附件编号唯一、计数器、绝对路径、资产及工单归属、唯一登记与至多
  一次撤销、登记在报修后且撤销在登记后，以及记录内容、撤销状态与履历是否
  一致。资料文件当前是否可用不参与整库一致性校验。
- 工具不做任何自动修复，也不提供修复入口：不补字段、不重编号、不删除记录，
  原文件字节保持不变。请人工修正 `caretrack.json`（或从备份恢复）后再继续使用。
- 每次写入前会再次校验待提交数据；校验或读写失败不会留下部分业务变化，
  也不会消耗工单编号或绑定请求标识，恢复有效数据或写入条件后可重新提交。
